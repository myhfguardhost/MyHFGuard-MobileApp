MYHFGUARD - CURRENT MEDICATION FINAL FIX (2026-08-21)
=====================================================

WHY THE LATEST ERROR HAPPENED
-----------------------------
The Profile page was incorrectly changed to insert each text line into the
`medication` table. Your deployed medication table has a required NOT NULL
column named `class`. Therefore an insert containing only patient_id/name/active
fails with PostgreSQL error 23502:

  null value in column "class" of relation "medication" violates not-null constraint

CORRECT PROJECT ARCHITECTURE
----------------------------
The project documentation already defines Profile Current Medication as:

  profiles.current_medication

The `medication` table is a separate/legacy structured medicine table and is
NOT the storage target for the free-text Profile field.

WHAT THIS VERSION CHANGES
-------------------------
1. Profile -> Save Current Medication only PATCHes
   `profiles.current_medication` again.
2. It no longer inserts/deletes rows in the `medication` table when the user
   presses Save Current Medication.
3. The Samsung TTS chooser fix is preserved.
4. The Medication read model understands the deployed table's `active` field
   and optional `class` value so existing structured records can still be read.
5. A one-time Supabase SQL fix is included to allow current_medication to be
   updated even after the one-time profile baseline is locked.

IMPORTANT ONE-TIME SUPABASE STEP
--------------------------------
Run:

  database_fixes/FIX_CURRENT_MEDICATION_PROFILE_LOCK.sql

in Supabase Dashboard -> SQL Editor -> New query -> Run.

Then rebuild/install this Android project and test:

  Furosemide 40 mg (noon)
  Bisoprolol 2.5 mg (noon)
  Sacubitril/Valsartan 24/26 mg (noon, night)

Expected result:
  Current medication saved.

No `frequency` or `class` column error should be generated by the Profile Save
button because the Profile page no longer writes to the medication table.
